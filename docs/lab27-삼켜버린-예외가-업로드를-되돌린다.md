# lab27 — 삼켜버린 예외가 업로드를 통째로 되돌린다

- 분야: 스프링 DB / 유형: 디버깅 / 난이도: 응용
- 패키지: `com.vryez.backendlab.lab27`
- 예상 소요: 1~2시간

## 배경 시나리오

동영상 게시판의 업로드 API(`POST /lab27/videos`)는 영상을 저장하면서 두 가지를 함께 처리한다.

1. 영상 레코드(`lab27_video`)와 영상 통계 레코드(`lab27_video_stat`, 조회수 0)를 저장한다. 이 둘은 **반드시 함께** 저장되거나 함께 없어야 한다.
2. 감사(audit) 로그 테이블(`lab27_upload_audit_log`)에 "누가 무슨 영상을 올렸는지"를 남긴다.

감사 테이블은 **다른 팀 소유의 레거시 테이블**이라 우리가 스키마를 바꿀 수 없고, 감사 규정상 **제목은 원문 그대로** 남겨야 한다(자르거나 가공 금지). 그런데 이 테이블의 `video_title` 컬럼이 `varchar(15)`로 작아서, **제목이 15자를 넘는 영상은 감사 적재가 실패한다.**

이번 스프린트의 요구사항 변경: **감사 로그 적재가 실패하더라도 영상 업로드 자체는 성공해야 한다.** 담당 개발자는 "로그 저장 호출을 try-catch로 감싸서 실패를 삼키면 되겠네" 하고 그렇게 고쳤다. 그리고 배포했다.

## 증상

- 제목이 짧은(감사 적재가 성공하는) 영상은 아무 문제 없이 업로드된다.
- 제목이 긴(감사 적재가 실패하는) 영상을 올리면, **분명히 try-catch로 예외를 잡아 무시했는데도** 업로드 API가 500을 반환한다.
- 실패한 것은 로그뿐이어야 하는데, **영상도, 영상 통계 레코드도 저장되지 않고 통째로 사라진다.**
- 서버 로그에는 "커밋을 요청했지만 트랜잭션이 롤백되었다"는 취지의 예외가 남는다.

감사 로그 실패는 우리가 받아들이기로 한 정상 상황이다(스키마도 못 바꾸고 제목도 못 자른다). 그런데 그 실패가 왜 멀쩡한 영상 업로드까지 되돌리는가? try-catch는 왜 무력한가? **원인을 찾아 고쳐라.**

## 완료 조건

채점 인수 테스트는 아래를 검증한다. 모든 단언은 **DB를 실제로 재조회**해서 확인한다(메모리상의 객체가 아니라 실제 저장 결과).

1. **정상 케이스(감사 적재 성공):** 제목이 짧은 영상을 업로드하면 영상 1건 + 영상 통계 1건 + 감사 로그 1건이 모두 저장되고, 예외가 발생하지 않는다.
2. **감사 실패 케이스:** 제목이 길어 감사 적재가 실패하는 영상을 업로드하면 — 영상은 **원문 제목 그대로** 저장되고, 영상 통계 레코드도 저장되며, **감사 로그만 저장되지 않는다.** 업로드는 성공으로 끝난다(롤백 예외가 호출자/클라이언트까지 전파되지 않는다).
3. **핵심 원자성 유지:** 감사가 실패하든 성공하든, 영상과 영상 통계는 **항상 함께** 저장되거나 함께 없어야 한다(둘 중 하나만 남는 일이 없어야 한다).
4. **회귀:** 영상 저장 자체가 실패하는 요청(예: 업로더 ID 누락)에서는 영상·영상 통계·감사 로그가 **모두** 저장되지 않는다(부가 작업만 격리한 것이지, 핵심 작업의 원자성을 깬 것이 아니어야 한다).
5. 감사 적재를 건너뛰었다는 사실이 로그로 관찰 가능해야 한다(무엇을, 왜 건너뛰었는지).

## 제약 (회피 금지)

- 감사 테이블의 스키마(컬럼 크기)를 변경하는 것은 금지.
- 감사에 남기는 제목을 잘라내거나 가공해 실패 자체를 없애는 방식은 요구사항 위반으로 인정하지 않는다.
- 감사 적재는 실패할 수 있다는 전제 위에서, 그 실패가 업로드를 오염시키지 않게 만드는 것이 과제다.

## 재현 방법

앱을 띄운 뒤(`./gradlew bootRun`):

```bash
# 성공 케이스
curl -i -X POST localhost:8080/lab27/videos \
  -H 'Content-Type: application/json' \
  -d '{"title": "짧은 제목", "uploaderId": "user-1"}'

# 증상 케이스 (제목 15자 초과)
curl -i -X POST localhost:8080/lab27/videos \
  -H 'Content-Type: application/json' \
  -d '{"title": "이 제목은 감사 로그 컬럼보다 훨씬 길어서 적재가 실패한다", "uploaderId": "user-1"}'
```
