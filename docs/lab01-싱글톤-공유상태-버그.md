# lab01 — 결제 금액 계산 API의 간헐적 오류 (디버깅형)

- 분야: 스프링 핵심원리 / 난이도: 기초 / 예상 소요: 30~60분
- 패키지: `com.vryez.backendlab.lab01`

## 배경 시나리오

`POST /lab01/orders` 는 주문 금액(`amount`)을 받아 정가에서 10%를 할인한 최종 금액(`finalPrice`)을 돌려주는 결제 계산 API다.

개발 중 단건 호출과 단위 테스트에서는 항상 정확히 `amount`의 90%가 나왔다. 그런데 부하 테스트로 **여러 주문이 동시에 몰리자**, 일부 응답의 `finalPrice`가 자기 `amount`의 90%와 맞지 않는 사례가 산발적으로 나타났다. 예를 들어 1,000원을 주문한 응답에 9,000원(=10,000원의 90%)이 담겨 오는 식이다.

재현은 **동시 요청일 때만** 되고, 순차로 하나씩 호출하면 멀쩡하다.

프로젝트에는 이 현상을 드러내는 동시성 테스트(`lab01.OrderPriceServiceConcurrencyTest`)가 이미 들어가 있고, **지금은 실패한다.** 원인을 찾아 고쳐라.

## 요구사항

- 동시 요청에도 각 응답이 자기 주문 금액에 정확히 대응하도록 만든다.

## 완료 조건

- 동시에 N개의 주문이 들어와도 각 응답의 `finalPrice`가 자신이 보낸 `amount`의 정확히 90%와 일치한다.
- 제공된 `OrderPriceServiceConcurrencyTest`가 **통과**한다.
- 왜 기존 단건/단위 테스트로는 이 버그를 잡지 못했는지 한 줄로 설명할 수 있다.

## 제약

- 테스트의 검증 조건이나 부하량(taskCount, 스레드 수)을 약화시키지 않는다.
- 엔드포인트·요청/응답 형식 등 기존 API 계약은 그대로 유지한다.
