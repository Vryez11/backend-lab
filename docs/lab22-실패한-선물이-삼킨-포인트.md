# lab22 — 실패한 선물이 삼킨 포인트

- 분야: 스프링 DB / 유형: 디버깅 / 난이도: 기초
- 패키지: `com.vryez.backendlab.lab22`
- 예상 소요: 45~60분

## 배경 시나리오

동영상 게시판에 **포인트 선물** 기능이 있다. 시청자가 크리에이터에게 포인트를 선물하면, 보낸 사람 잔액에서 금액만큼 빠지고 받는 사람 잔액에 그만큼 쌓인다.

최근 CS로 이런 신고가 들어왔다.

> "정지된 크리에이터에게 잘못 선물을 눌렀더니 화면에 **'선물 실패'**라고 떴어요. 실패한 거면 아무 일도 없어야 하는 거 아닌가요? 그런데 제 포인트는 선물한 만큼 그대로 사라졌어요. 상대방한테 갔는지 확인해보니 그쪽은 한 푼도 안 늘었고요."

재현해보면 실제로 그렇다. **정지된 계정에 선물을 시도하면 예외로 정상 차단되는데, 보낸 사람의 잔액만 선물 금액만큼 줄어들고 받는 사람 잔액은 그대로다.** 실패로 끝난 요청이 보낸 쪽 잔액만 갉아먹고 있다.

- 단건 요청으로 **100% 재현**된다. 동시성·부하·타이밍과 무관하다.
- 정상(정지되지 않은) 계정에 선물하는 경로는 겉보기에 문제없이 동작한다.

이 장애를 재현하고, 원인을 찾아 고쳐라.

## 스캐폴드

| 파일 | 역할 |
|---|---|
| `Account` | 계정 도메인 (id, name, balance, suspended) |
| `AccountRepository` | JdbcTemplate 기반 조회·잔액 증감 |
| `GiftPointService` | 선물 로직 진입점 `gift(fromId, toId, amount)` |
| `Lab22Config` | `account` 테이블 DDL + 시드 3행 초기화 |

시드 데이터: `1 시청자보내는사람(잔액 1000)`, `2 정지크리에이터(잔액 0, 정지)`, `3 정상크리에이터(잔액 0)`.

## 완료 조건

- 정지된 계정에 선물을 시도하면 예외로 실패하고, **보낸 사람과 받는 사람의 잔액이 둘 다 선물 이전 그대로**여야 한다(부분 반영 없이 전액 원복).
- 정상 계정에 선물하면 보낸 사람은 정확히 금액만큼 감소하고, 받는 사람은 동일 금액만큼 증가한다.
- 위 두 조건을 함께 검증하는 인수 테스트가 통과한다. 성공·실패 경로 모두에서 **양쪽 잔액을 모두 단언**할 것(한쪽만 확인 금지).

## 제약

- 예외를 `try-catch`로 잡아 손으로 차감분을 되돌리는 식(수기 보상 로직)으로 때우지 말 것. 프레임워크의 트랜잭션이 **실제로** 동작하도록 고친다.
- 재현 테스트는 버그를 고친 뒤에도 깨지지 않게 작성한다(최종 잔액 기준으로 검증).
