# lab20 — 공개 영상 조회 로그에 관리자 이름이 찍힌다 (디버깅 · 변형복습 · 기초)

## 배경 시나리오

동영상 게시판에 보안 **감사(audit) 로그**가 새로 붙었다. 
모든 요청은 접근 로그(AccessLog)에 "누가(actor) 어떤 경로를 호출했는지"를 한 줄씩 남긴다.

- 관리자 작업(영상 삭제 등)은 `X-Admin-Id` 헤더로 식별되어 actor에 **관리자 ID**가 찍힌다.
- 헤더가 없는 **공개 요청**(영상 조회·신고)은 actor가 반드시 **`anonymous`** 여야 한다.

## 증상

운영에 올린 뒤, **트래픽이 한산한 시간대에만** 이상한 감사 로그가 발견됐다.

- 아무 관리자 권한도 없는 **공개 영상 조회 요청**의 접근 로그 actor 자리에, **방금 전 다른 관리자의 ID**가 찍혀 있다.
- 특히 관리자가 **존재하지 않는 영상을 삭제하려다 실패(에러)한 직후**의 공개 요청에서 자주 나타난다.
- 요청이 몰리는 낮 시간에는 거의 재현되지 않는다.

결과적으로 "이 관리자가 이 공개 영상을 열람했다"는 **잘못된 증거**가 감사 추적에 남는다.

## 할 일

제공된 lab20 스캐폴드는 정상적인 단일 요청에서는 잘 동작한다.

1. 위 증상을 **재현**하고,
2. 원인을 **제거**하고,
3. 다시는 재현되지 않도록 **회귀 테스트로 고정**하라.

## 요구사항

- actor 판별 규칙 유지: `X-Admin-Id` 헤더가 있으면 그 ID, 없으면 `anonymous`.
- 존재하지 않는 영상 삭제 시도는 지금처럼 **에러 응답(4xx/5xx)** 이어야 한다 — 예외를 삼켜 200으로 만들면 안 된다.
- 심어 둔 인수 테스트(`Lab20AcceptanceTest`, `RequestAuditFilterTest`)는 **수정하지 않고** 전부 green으로 만든다. 회귀 테스트 추가는 자유.

## API (스캐폴드 제공)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/lab20/admin/videos/{id}/delete` | 관리자 삭제 (X-Admin-Id 헤더) |
| GET | `/lab20/videos/{id}` | 공개 조회 |
| POST | `/lab20/videos/{id}/reports` | 공개 신고 |

시드 영상: id 1, 2.

## 완료 조건

1. `X-Admin-Id: admin-1`로 **존재하는 영상 삭제** → 그 요청의 접근 로그 actor = `admin-1`, 응답 성공.
2. 삭제 성공 직후 **헤더 없는 공개 조회** → actor = `anonymous`.
3. `X-Admin-Id: admin-2`로 **존재하지 않는 영상 삭제**를 시도해 에러가 난 **직후**의 헤더 없는 공개 요청 → actor = `anonymous` (관리자 ID가 새지 않는다).
4. 서로 다른 관리자(admin-1, admin-2)가 연속으로 작업해도 각 접근 로그 actor가 각자 정확하다.
5. 위 3·4가 **단일 워커 스레드**(`server.tomcat.threads.max=1`) 환경에서 **결정적으로** 통과한다.
6. 임의의 요청 처리가 끝난 뒤, 워커 스레드에 요청 컨텍스트 **잔여값이 남지 않는다.**
