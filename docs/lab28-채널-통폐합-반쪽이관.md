# lab28 — 채널 통폐합 중 이관이 반쪽만 적용된 채 멈췄다

- 분야: 스프링 DB / 유형: 변형복습(디버깅) / 난이도: 응용
- 패키지: `com.vryez.backendlab.lab28`
- 예상 소요: 1~1.5시간

## 배경 시나리오

크리에이터가 여러 채널을 하나로 통폐합하면서, 영상 여러 개를 **채널 A → 채널 B로 한 번에 이관**하는 운영 기능이 있다. 영상 한 개를 이관할 때마다:

1. 그 영상의 소속 채널을 B로 바꾸고
2. 채널 A의 영상 수를 1 줄이고 채널 B의 영상 수를 1 늘리며
3. 이관 감사 로그(`transfer_log`)를 1건 남긴다.

운영 규칙:

- **전부 성공 아니면 전부 취소(원자성).** 요청한 영상 목록 중 하나라도 이관할 수 없으면, 그 배치에서 앞서 처리된 영상들도 원래 채널에 그대로 있어야 하고 채널별 영상 수도 손대기 전과 같아야 한다.
- 신고가 누적돼 **잠긴 영상(`status = 'LOCKED'`)** 은 이관 대상이 될 수 없다. 목록에 잠긴 영상이 섞여 있으면 그 배치 전체가 취소돼야 한다.

## 증상

채널 A의 영상 5개 중 하나가 잠긴 상태였는데, 그 잠긴 영상을 포함해 여러 개를 한꺼번에 이관 요청했더니 도중에 멈췄다. 그런데:

> "취소됐어야 할 **앞쪽 영상들은 이미 채널 B로 넘어가 있고**, 두 채널의 영상 수 표시도 실제 소속과 어긋나 버렸어요. 다시 이관을 시도하면 이번엔 이미 옮겨진 영상들 때문에 숫자가 더 벌어져요."

- 코드에는 이미 롤백 관련 설정이 들어가 있는데도 이 현상이 재현된다.
- 스캐폴드는 정상 기동하며, 위 증상을 그대로 재현하는 인수 테스트가 함께 들어 있다(현재 1개 실패).

원인을 찾아 고치고, 고친 뒤 같은 시나리오를 다시 돌려 **원복까지 검증**하라.

## 스캐폴드

| 파일 | 역할 |
|---|---|
| `VideoTransferService` | 일괄 이관 진입점 `transferAll(from, to, videoIds)` |
| `VideoTransferRepository` | JdbcTemplate 기반 데이터 접근 + 테스트 검증용 조회 메서드 |
| `LockedVideoException` | 잠긴 영상에서 던지는 예외 |
| `Video`, `Channel` | 도메인 레코드 |
| `src/test/resources/lab28/schema.sql` | `channel` + `video` + `transfer_log` DDL |
| `src/test/resources/lab28/data.sql` | 시드 — 채널 A(영상 5개)·B(0개), 영상 101~105 |
| `VideoTransferServiceTest` | 증상 재현 인수 테스트 2건 |

시드 데이터: 영상 101·102·104·105는 `ACTIVE`, **103은 `LOCKED`**. 모두 채널 A(id=1) 소속, 채널 B(id=2)는 비어 있다.

## 완료 조건

- **정상 이관**: 잠긴 영상이 없는 목록을 이관하면, 대상 영상 전부의 소속 채널이 B로 바뀌고, 채널 A·B의 영상 수가 정확히 반영되며, 이관 건마다 `transfer_log`가 남는다.
- **원자성(핵심)**: 목록 중간에 잠긴 영상이 섞여 이관이 중단되면, **그 배치에서 아무 영상도 이관되지 않은 상태**여야 한다 — 앞서 처리되던 영상들의 소속 채널·두 채널의 영상 수·`transfer_log`가 모두 이관 시도 이전과 동일하다.
- 잠긴 영상이 원인인 실패는 호출자에게 예외로 드러나야 하며, 성공한 것처럼 조용히 삼켜지지 않는다.
- 수정 후 인수 테스트가 모두 통과하고, **같은 시나리오를 다시 실행해도 데이터가 오염되지 않고 반복 가능**하다.

## 제약

- 예외를 `try-catch`로 삼켜 실패를 감추거나, 손으로 되돌리는 보상 쿼리로 원자성을 흉내 내지 말 것. 프레임워크의 트랜잭션이 **실제로** 동작하도록 고친다.
- 잠긴 영상을 미리 조회해서 걸러내는 식으로 예외 상황 자체를 우회하지 말 것 — 배치 도중 실패가 나도 원자성이 지켜지는 구조를 만드는 것이 목표다.
- 자체 검증 시 테스트 클래스/메서드에 `@Transactional`을 붙이지 말 것 — 테스트 트랜잭션이 끝에 모든 쓰기를 롤백해 버려, 실제로 커밋되어 남는지를 검증할 수 없다.
- 스키마·시드는 `@Sql({"/lab28/schema.sql", "/lab28/data.sql"})`로 매 테스트 초기화된다.
