# lab03 — 동영상 검색·등록 API: 요청 파라미터 바인딩과 응답 (TDD)

- 분야: 스프링 MVC / 난이도: 기초 / 유형: TDD
- 패키지: `com.vryez.backendlab.lab03`
- 예상 소요: 40~60분

## 배경 시나리오

동영상 게시판 서비스의 첫 백엔드 API를 세운다. 아직 화면도 DB도 없다 — 오직 HTTP 요청이
들어오면 컨트롤러가 그 데이터를 어떻게 받아들이고, 어떤 형태로 응답을 돌려주는지를 코드로
증명하는 단계다.

**이 과제는 TDD 방식이다.** 로컬에 이미 **실패하는 인수 테스트 8개**(`VideoControllerTest`)와
아무것도 구현하지 않은 **컨트롤러 스텁**(`VideoController`)이 깔려 있다. 테스트를 먼저 읽어
요구되는 HTTP 계약을 파악하고, 스텁을 채워 빨간 막대를 하나씩 초록으로 바꾸는 것이 목표다.

다룰 개념은 하나로 묶인다 — **스프링 MVC가 요청 데이터를 컨트롤러 파라미터로 바인딩하는
방식과, 응답을 만들어내는 방식.** 검색은 쿼리 파라미터로, 등록은 HTML 폼으로 들어온다.
응답은 JSON이며 등록은 201을 돌려줘야 한다.

## 요구사항

- 대상 엔드포인트: `GET /api/videos`(검색), `POST /api/videos`(등록)
- 저장소는 인메모리로 충분하다(스텁에 이미 시드 데이터 3건이 들어 있다). DB는 쓰지 않는다.
- `store`·`seq`·`save()`는 그대로 두고, 두 핸들러의 시그니처와 본문만 채운다.

## 완료 조건

제공된 인수 테스트 8개가 모두 green이 되면 완료다. 테스트가 검증하는 계약:

- `GET /api/videos?keyword=spring` → 제목에 `keyword`가 포함된 동영상들을 **JSON 배열**로 반환(200). 대소문자는 무시한다.
- `keyword`는 **필수**다. 누락하면 **400**을 반환한다.
- `limit` 파라미터는 **생략 시 기본값 10**, 지정 시 그 개수만큼만 반환한다.
- 매칭이 하나도 없으면 **200 + 빈 배열**을 반환한다.
- `POST /api/videos`에 **폼(application/x-www-form-urlencoded)**으로 `title`, `uploader`, `durationSec`를 보내면 → **201 Created** + 서버가 부여한 `id`를 포함한 생성 리소스를 **JSON**으로 반환한다.
- 방금 등록한 동영상은 이후 검색으로 조회된다(실제로 저장됐음).
