# lab15 — 몰릴수록 사라지는 조회수 (변형복습)

- 분야: 스프링 핵심원리 / 난이도: 기초 / 유형: 변형복습
- 패키지: `com.vryez.backendlab.lab15`
- 예상 소요: 30~60분

## 배경 시나리오

급상승 중인 라이브 방송(단일 인기 영상)의 실시간 **조회수**를 집계하는 API가 운영에 올라갔다. 평소에는 멀쩡한데, 
방송이 화제가 되어 시청자가 **한꺼번에 몰리는 순간**부터 민원이 들어온다 — 대시보드에 찍힌 조회수가 **실제 들어온 조회 요청 수보다 적게** 나온다. 
접근 로그를 세어 보면 분명 10만 번 호출됐는데 집계는 9만 몇천에서 멈춰 있다. 트래픽이 셀수록 격차가 벌어진다.

- 개발자가 로컬에서 버튼을 한 번씩 눌러 보면(단일 요청) 조회수는 정확히 1씩 잘 오른다. **수동 테스트로는 절대 재현되지 않는다.**
- 서버는 정상 기동하고 에러 로그도 없다. 예외가 터지는 게 아니라 **숫자가 조용히 샌다.**

당신의 임무: 이 "조용히 새는 조회수"를 **자동화된 테스트로 재현**하고, 원인을 스스로 규명한 뒤, 집계가 정확해지도록 고쳐라.

## 주어진 코드

- `VideoViewService` — 조회수 집계 서비스
- `VideoViewController` — `POST /api/videos/trending/view` (조회 1건 발생), `GET /api/videos/trending/views` (현재 집계 조회)

단일 급상승 영상 1개만 집계한다고 가정한 단순화다(단일 카운터, id 파라미터 없음).

## 완료 조건

- 동시에 대량의 조회 요청이 몰려도 최종 조회수가 **실제 요청 수와 정확히 일치**한다.
- 이 불일치를 **재현하는 동시성 테스트**가 존재하고, 수정 전에는 **실패**, 수정 후에는 **통과**한다.
- 재현 테스트는 모든 요청 스레드의 **완료를 기다린 뒤**, 느슨한 단언("예외 없음", "0보다 큼", 타입만)이 아니라 **정확한 기대 수치**(예: 정확히 100000)를 단언한다.
- 원인을 스스로 규명해 한 문단으로 적고, **어떤 방식으로** 정확성을 회복했는지 근거를 남긴다.

## 제약

- 재현 테스트를 먼저 작성해 실패를 확인한 뒤 수정에 들어간다 — "돌려보니 되더라"는 인정하지 않는다.
- 추가 의존성 없이 기존 프로젝트 구성으로 해결한다.
