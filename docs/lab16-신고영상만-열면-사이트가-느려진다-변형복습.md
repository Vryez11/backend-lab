# lab16 — 신고 영상만 열면 사이트가 느려진다 (변형복습)

## 배경 시나리오

동영상 게시판을 운영 중이다. 신고(reported)가 접수된 영상은 상세 페이지에서 신고 사유를 함께 보여준다.

그런데 며칠 전부터 이상한 장애 제보가 들어온다. 
평소엔 멀쩡한데, **신고가 들어온 영상들의 상세 페이지를 연달아 몇 번 열고 나면** 그 뒤로는 조회수 증가, 목록 개수 조회 같은 **전혀 상관없어 보이는 기능까지** 한 박자(약 1초) 멈췄다가 실패하기 시작한다. 
서버를 재시작하면 잠깐 괜찮아졌다가, 신고 영상을 몇 번 더 열면 같은 증상이 재발한다. 일반(신고 아님) 영상만 계속 열 때는 아무리 많이 열어도 멀쩡하다.

## 요구사항

1. 이 장애를 **재현하는 테스트**를 먼저 작성한다. 단순히 "예외가 난다"가 아니라, 이 실패가 **다른 종류의 실패(예: 즉시 터지는 SQL 오류)가 아니라 바로 이 장애**임을 코드가 증명하도록 단언한다.
2. 원인을 찾아 고친다. 신고 영상 상세를 몇 번을 열어도 이후 조회가 즉시 정상 동작해야 한다.
3. 고치는 과정에서 **다른 조회 로직에 회귀를 넣지 않았음**을 테스트로 보장한다.

## 완료 조건

1. **누수 제거.** 신고된 영상의 상세 조회를 풀 최대 크기보다 많이(예: 10회) 반복한 뒤에도, 임의의 다른 조회(전체 영상 개수 `countAll()` 등)가 **즉시(연결 대기 없이) 성공**한다.
2. **재현 테스트의 질.** 장애를 재현·회귀 방지하는 테스트가, 실패를 **풀 고갈로 특정**한다. 즉 예외 타입만 단언하지 말고 다음 두 가지를 함께 단언한다.
   - (a) 문제의 호출이 **커넥션 획득을 기다린 경과시간이 `connectionTimeout` 이상**이었다는 점 (즉시 실패가 아님)
   - (b) 던져진 예외의 **메시지 또는 원인 체인(`getCause`)이 커넥션 획득 타임아웃**임을 가리킨다는 점
   - (a) 또는 (b) 단언을 지우면, 이 테스트가 즉시 터지는 SQL 오류 같은 **다른 실패와 풀 고갈을 구분하지 못하게 됨**을 스스로 확인한다.
3. **누수의 국소성 증명.** 일반(신고 아님) 영상은 **아무리 많이 조회해도** 풀이 고갈되지 않는다. 즉 누수가 신고 경로에만 한정됨을 테스트로 보인다.
4. **회귀 없음.** 수정 후 `findById`, `increaseViewCount`, `countAll` 등 기존 조회가 정상값을 그대로 반환한다.

## 제약

- 전용 인메모리 DB(`jdbc:h2:mem:videolab16`)를 쓰는 별도 커넥션 풀로 앱 전체와 격리되어 있다. 풀 파라미터는 `VideoLabDataSourceConfig.POOL_SIZE`(3), `CONN_TIMEOUT_MS`(1000)으로 노출되어 있으니 테스트에서 매직넘버 대신 이 상수를 참조한다.
- 풀 크기를 키우는 등 **설정 변경으로 증상만 회피하는 수정은 무효**다. 원인을 코드에서 찾아 고친다.
- 채점은 컨트롤러가 아니라 service/repository 레벨에서 이뤄진다. 컨트롤러(`GET /lab16/videos/{id}`, `GET /lab16/videos/count`)는 시나리오 재현용이다.
