# lab07 — 숨긴 삭제 버튼, 그런데 뚫리는 삭제 API

- 유형: 디버깅 / 난이도: 기초 / 분야: 스프링 MVC
- 패키지: `com.vryez.backendlab.lab07`
- 예상 소요: 30~60분

## 배경 시나리오

당신은 사내 동영상 스트리밍 서비스(토스 영상 클론)의 백엔드를 맡고 있다. 화면에는 영상 목록이 뜨고, 영상 삭제 기능이 있다. 제품 요구사항은 명확하다 — **영상 삭제는 관리자(ADMIN)만 할 수 있어야 한다.**

프론트엔드는 `GET /lab07/videos` 응답에 담긴 `canDelete` 값을 보고, 관리자에게만 삭제 버튼을 그려 준다. 일반 회원 화면에는 삭제 버튼 자체가 없다.

**장애 신고.** 어젯밤 고객지원팀에 *"내가 올린 영상이 사라졌다"* 는 신고가 여러 건 접수됐다. 접근 로그를 열어 보니, **관리자가 아닌 일반 회원 계정**이 영상 삭제 요청을 보냈고, 서버는 그 요청을 아무 문제 없이 정상 처리(200 OK)했다. 그 회원의 화면에는 애초에 삭제 버튼이 보이지도 않았는데, 영상은 실제로 지워졌다.

## 임무

이 장애를 로컬에서 그대로 재현하고, **관리자가 아닌 사용자는 어떤 경로로도 영상을 삭제할 수 없도록** 바로잡아라. 브라우저 화면이 아니라 API를 직접 두드리는 요청까지 막아야 한다.

### 재현 절차 (버그가 살아 있는 상태)

```bash
# 1) viewer(일반 회원)로 로그인 — 세션 쿠키 저장
curl -c /tmp/viewer.txt -H 'Content-Type: application/json' \
     -d '{"loginId":"viewer","password":"viewer1234"}' \
     http://localhost:8080/lab07/login

# 2) 목록 조회 — canDelete는 전부 false (버튼이 안 보이는 상태)
curl -b /tmp/viewer.txt http://localhost:8080/lab07/videos

# 3) 그런데 삭제 API를 직접 호출하면...
curl -b /tmp/viewer.txt -X DELETE http://localhost:8080/lab07/admin/videos/1
# → 200 OK, 영상이 실제로 지워진다. 이것이 잡아야 할 장애다.
```

계정: `admin`/`admin1234`(ADMIN), `viewer`/`viewer1234`(USER). 저장소는 인메모리라 앱을 재시작하면 시드 데이터가 복원된다.

## 완료 조건

- 비로그인 사용자가 삭제 API를 직접 호출하면 **401**로 거부되고, 영상은 그대로 남아 있다.
- 로그인은 했지만 관리자가 아닌 사용자가 삭제 API를 **UI를 거치지 않고 직접 호출**해도 **403**으로 거부되고, 영상은 그대로 남아 있다.
- 관리자 사용자는 삭제 API로 영상을 정상 삭제(**200**)할 수 있다.
- `GET /lab07/videos`의 `canDelete`는 관리자에게 `true`, 그 외에는 `false`로 나온다(기존 요구사항 유지).
- 삭제 권한 검증을 여러 컨트롤러에 복사·분산하지 않고, **공통 관심사로 한 곳에서** 처리한다.
