# lab26 — 동시 업로드가 겹치면 남의 영상 정보가 돌아온다 (디버깅형 · 기초)

## 배경 시나리오

스트리밍 클론의 영상 업로드 API를 운영 중이다. 클라이언트가 영상을 올리면 서버가 저장 후 방금 만들어진 영상의 정보(영상 ID·제목·업로더 ID)를 응답으로 돌려주고, 프론트는 그 응답으로 "업로드 완료" 화면을 그린다.

개발·테스트 환경에서는 아무 문제가 없었고, 배포 후 한산한 시간대에도 멀쩡했다. 그런데 신규 영상이 많이 몰리는 저녁 피크 타임에 CS가 들어왔다:

- "방금 올린 내 영상인데 완료 화면에 **모르는 제목**이 떠 있다"
- "업로더가 **내가 아닌 다른 사람 ID**로 찍혔다"

재현을 시도하면 혼자 한 건씩 올릴 때는 절대 안 나고, 여러 사용자가 거의 동시에 업로드할 때만 간헐적으로 터진다. 심하면 남이 올린 영상의 제목이 내 응답에 노출되어, 비공개로 준비 중이던 제목이 남에게 보이는 사고로 번질 수 있다.

## 대상 코드

`com.vryez.backendlab.lab26` 패키지 — `POST /lab26/videos`

// 요청
```json
{ "title": "내 영상 제목", "uploaderId": 7 }
```

// 응답
```json 
{ "videoId": 1, "title": "내 영상 제목", "uploaderId": 7 }
```

앱은 정상 기동하고 단건 업로드는 성공한다.

## 할 일

1. 동시 업로드 상황에서 응답이 뒤섞이는 현상을 **직접 재현**한다.
2. 원인을 규명하고 고친다.
3. 고친 상태에서 다시 재현이 안 되는지 **재검증**한다.
4. 재현을 자동화한 **회귀 테스트**를 저장소에 남긴다.

## 완료 조건

- 여러 요청이 동시에 들어와도, 각 업로드 응답의 **제목·업로더 ID가 그 요청이 보낸 값과 정확히 일치**한다 (한 요청의 값이 다른 요청 응답에 절대 섞이지 않는다).
- 단건 업로드는 종전대로 정상 동작한다 (영상 ID가 부여되고, 제목·업로더 ID가 그대로 반향된다).
- 동시성 상황을 재현하는 **자동화 테스트**가 저장소에 존재하고, 수정 전에는 이 현상을 잡아냈으며 수정 후에는 통과한다. 이 테스트는 **버그 코드의 존재에 의존하지 않아**, 버그가 사라진 뒤에도 계속 유효한 회귀 테스트여야 한다 (요청을 보내고 응답만 검증하는 형태).

## 제약

- 처리량을 인위적으로 직렬화(요청을 한 줄로 세워 한 번에 하나씩만 처리)하는 방식으로 증상을 덮지 않는다 — 동시 처리 능력은 유지되어야 한다.
- 코드에 있는 후처리 대기 시뮬레이션(`Thread.sleep`)은 운영 환경의 후처리 지연을 모사한 것이다. 제거해서 테스트를 통과시키지 말 것.
