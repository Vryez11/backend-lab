# lab14 — 영상이 늘자 목록이 버벅인다: 동영상 게시판 페이징·정렬 (변형복습)

## 배경 시나리오

치지직 클론 0단계로 만들고 있는 **동영상 게시판**. 
지금 `GET /lab14/videos`는 전체 영상을 한 번에 통째로 내려준다. 
영상이 수십 개로 늘자 프론트에서 요구사항이 바뀌었다.

> "목록을 페이지 단위로 끊어서 주세요. 정렬도 최신순/오래된순/조회수순 세 가지 필요합니다. 
> 그리고 **파라미터를 아무것도 안 붙여도** 첫 페이지가 최신순으로 그냥 나와야 해요."

스캐폴드에는 인메모리 `VideoRepository`(영상 23개 시드), 응답 DTO, 컨트롤러, 
그리고 **스텁 상태의 `VideoListService.list()`** 가 준비돼 있다. 
지금은 항상 빈 목록을 반환한다 — 이 스텁을 채우는 것이 과제다.

## 요구사항

- `GET /lab14/videos`에 쿼리 파라미터 `page`(0부터), `size`, `sort`(`latest` | `oldest` | `views`)를 받는다. **셋 다 생략 가능** — 생략 시 `page=0`, `size=10`, `sort=latest`로 동작한다.
- 응답은 JSON 객체다: `{ "content": [ ...영상들... ], "page": 0, "size": 10, "totalCount": 23 }`. `content`의 각 원소는 `id`, `title`, `views`, `createdAt`를 가진다.
- `sort=latest`는 등록일 **내림차순**(최신이 위), `oldest`는 오름차순, `views`는 조회수 **내림차순**.
- **어떤 파라미터 조합에서도 정확해야 한다.** 특히
  1. 파라미터가 전혀 없을 때
  2. 마지막 페이지(남은 개수가 `size`보다 적을 때)
  3. 데이터보다 큰 `page`를 요청했을 때

  — 셋 다 터지지 않고 올바른 결과를 준다.

## 완료 조건

- 파라미터 없이 `GET /lab14/videos` → 200, `content` 10개, 최신 등록순(내림차순), `page=0`, `size=10`, `totalCount`=전체 개수.
- `page`/`size`를 지정하면 정확히 그 구간(윈도우)만 반환한다.
- `sort=oldest` → 가장 오래된 영상이 `content[0]`. `sort=views` → 조회수가 가장 큰 영상이 `content[0]`.
- 마지막 페이지 요청 시 남은 개수만 반환하고, 인덱스 초과로 예외가 나지 않는다.
- 존재하는 데이터보다 큰 `page`를 요청하면 `content`는 빈 배열이지만 `totalCount`는 전체 개수 그대로다(예외 아님).
- 응답 바디가 위 JSON 구조(객체 + `content` 배열)로 직렬화된다.
- 컨트롤러/서비스 코드에 요청 파라미터 null 분기가 없다 — 기본값은 바인딩으로 주어진다.
- **본인이 작성한 테스트가 "정렬 방향", "totalCount 값", "페이지 경계(마지막/초과 페이지)"를 각각 따로 단언한다.** `content` 개수만 세고 통과시키지 말 것.

## 제약

- **컨트롤러/서비스 어디에서도 요청 파라미터의 null 여부를 직접 분기하지 말 것.** 기본값은 `if (sort == null)` 같은 코드가 아니라 스프링 바인딩에 맡긴다.
- `page`/`size`가 음수인 등 비정상 입력에 대한 검증(400 응답)은 이번 과제 범위 밖이다. 정상 범위 입력과 "생략"만 다룬다.

예상 소요: 45~60분.
