# lab19 — 배포 직후 모든 썸네일이 깨졌다 (디버깅 · 기초)

## 배경 시나리오

동영상 스트리밍 서비스의 영상 목록 화면에서, 방금 배포한 직후부터 **모든 썸네일 이미지가 깨져서(엑스박스로) 보인다**는 장애가 접수됐다.

프런트 팀이 목록 API(`GET /lab19/videos`) 응답을 열어 보니, 각 항목의 `thumbnailUrl` 값이 전부 문자열 **`null`로 시작**하고 있었다.

```json
{ "id": 1001, "title": "클로드 코드 입문", "thumbnailUrl": "null/th/v1001.jpg", "viewCount": 52000 }
```

- 앱은 정상 기동한다. 에러 로그도 없다.
- DB에는 영상 데이터가 정상적으로 들어 있다.
- 목록 API도 200을 준다 — 다만 `thumbnailUrl`만 저렇게 망가진 채로 나온다.
- CDN 주소는 설정값(`app.cdn-base-url`)으로 관리되고 있고, 값 자체는 `https://cdn.example.com`으로 멀쩡히 들어 있다.

**원인을 찾아 고쳐라.** 목록 API가 설정된 CDN 주소를 반영한 정상 썸네일 URL을 주도록 만든다.

## 요구사항

- `GET /lab19/videos` 응답의 **모든** 항목에서 `thumbnailUrl`이 설정된 CDN base(`app.cdn-base-url`)로 시작해야 한다. 
  - 즉 `https://cdn.example.com/th/{key}.jpg` 형식이며, 어떤 항목도 `null`을 포함하지 않는다.
- CDN base 설정값을 다른 값으로 바꾸면(예: `https://cdn.other.com`) 응답의 `thumbnailUrl`도 그 값을 그대로 따라야 한다. 
- **주소 문자열을 코드에 하드코딩해 우회하는 것은 수정이 아니다.**
- 앱은 여전히 정상 기동하고, 목록 API는 200과 기존 영상 데이터를 정상적으로 반환한다.

## 완료 조건

- 채점용 인수 테스트가 모두 통과한다.
  - 모든 `thumbnailUrl`이 CDN base로 시작하고 `null`을 포함하지 않는다.
  - 설정값을 바꿔 띄우면 바뀐 값이 그대로 반영된다.
  - 목록 API가 200과 시드 데이터(조회수 내림차순)를 유지한다.
