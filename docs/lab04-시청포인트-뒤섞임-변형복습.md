# lab04 — 재발한 시청 포인트 뒤섞임 장애 (변형복습)

## 배경 시나리오

스트리밍 서비스의 시청 포인트 적립 API를 운영 중이다. `POST /lab04/watch` 는 사용자가 어떤 동영상을 몇 초 시청했는지(`userId`, `videoId`, `watchedSeconds`)를 받아 **10초당 1포인트**를 적립하고, 어떤 동영상으로 몇 포인트를 적립했는지(`videoId`, `earnedPoints`)를 돌려준다.

단건 호출과 순차 테스트에서는 항상 정확하다. 그런데 저녁 피크 시간대에 시청 종료 요청이 몰리면, 일부 사용자의 응답에 **본 적 없는 동영상 ID와 엉뚱한 포인트**가 담겨 온다는 신고가 들어온다. `userId` 는 항상 본인 것이 맞다.

이 증상은 이번이 처음이 아니다 — 몇 주 전에도 같은 신고가 있었고 "동시성 버그 수정" 커밋이 배포됐지만, 장애는 재발했다. 이번에는 원인을 뿌리째 뽑아야 한다.

## 요구사항

- 동시 요청 시에도 각 응답의 `videoId` · `earnedPoints` 가 자기 요청에 정확히 대응하게 만들어라.
- **운영 SLA**: 동시 100건을 전체 0.3초 이내에 처리해야 한다. 수정이 SLA를 깨면 배포할 수 없다.

## 완료 조건

- `WatchPointServiceConcurrencyTest` 의 테스트 2개가 모두 통과한다.
  - 정확성: 동시 100건에서 각 응답이 자기 요청의 `videoId` · 포인트와 일치
  - SLA: 동시 100건 전체 처리 시간 300ms 이내
- 테스트의 검증 조건이나 부하량을 약화시키지 않는다.
- 엔드포인트 · 요청/응답 형식 등 기존 API 계약은 그대로 유지한다.
- 이전 "동시성 버그 수정"이 왜 장애를 막지 못했는지 설명할 수 있다.

## 제약

- 예상 소요 시간: 30~60분
- 채점 시 개념 확인 질문 2~3개가 있다.
