# lab17 — 로그인 안 했는데 남의 계정이 보인다 (디버깅형 · 자바 동시성 · 기초)

## 배경 시나리오

동영상 게시판(스트리밍 클론 0단계)에 로그인 사용자 정보를 어디서나 꺼내 쓰는 `UserContext`를 도입했다. 
요청이 들어오면 인증 필터가 사용자를 확인해 컨텍스트에 담고, 컨트롤러·서비스 어디서든 파라미터로 넘기지 않고 이 컨텍스트에서 현재 사용자를 읽는다.

인증은 단순화되어 있다: 요청 헤더 `X-User-Id`에 사용자 id가 실려 오면 로그인한 것으로 간주한다. 
마이페이지는 `GET /api/lab/me`로 조회하고, 로그인 사용자면 `{"userId": …, "nickname": "…"}`을, 
비로그인이면 401과 `{"error": "unauthenticated"}`를 돌려준다. 시드 사용자는 (1, 철수), (2, 영희), (3, 민수) 세 명이다.

로컬에서 혼자 테스트할 땐 마이페이지가 항상 내 정보를 정확히 돌려줬다. 그런데 베타 오픈 후 문의가 들어왔다.

> "로그인 안 하고 그냥 들어왔는데 마이페이지에 **모르는 사람 닉네임과 시청기록**이 떠요."

> "로그아웃했는데 새로고침하면 아까 그 계정으로 다시 로그인된 것처럼 보여요. 항상 그런 건 아니고 **사람 많은 시간대에 가끔** 그래요."

혼자 재현하려 하면 잘 안 되는데, 트래픽이 몰릴수록 빈도가 올라간다. 비로그인·로그아웃 사용자에게 **직전에 그 서버를 거쳐 간 다른 사용자의 신원이 노출**되는, 명백한 보안 사고다.

## 요구사항

이 증상을 **테스트로 확실히 재현**하고, 근본 원인을 찾아 고친 뒤, 다시 재발하면 잡아내는 회귀 테스트를 남겨라.

## 완료 조건

1. `X-User-Id` 헤더로 사용자 1번을 실어 `GET /api/lab/me`를 부르면 200과 사용자 1번의 닉네임이 온다.
2. **직후 같은 워커 스레드에서**, 인증 정보 없이(헤더 없이) `GET /api/lab/me`를 부르면 이전 사용자가 아니라 **401(미인증)** 이 와야 한다.
3. 존재하지 않는 사용자 id로 요청한 뒤 이어진 요청에서도, 직전 사용자의 신원이 절대 새어 나오지 않는다.
4. 위 누수를 **재현하는 테스트**가 있고, 수정 후에는 그 테스트가 통과한다. 수정 코드를 되돌리면(버그 재삽입) 테스트가 다시 실패해야 한다(= 버그 존재 여부를 실제로 판별하는 테스트).
5. 정상 흐름뿐 아니라 **요청 처리 중 예외가 나도** 다음 요청에 신원이 새지 않는다.

## 제약

- `UserContext`를 파라미터로 넘기는 전면 리팩토링 금지 — 컨텍스트 구조는 유지한 채 버그만 찾아 고친다.
- 추가 의존성 금지 — 기본 의존성(webmvc/jdbc/validation, Lombok, H2)만으로 해결한다.
- 예상 소요 시간: 30~60분
