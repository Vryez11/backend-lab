# lab13 — 남의 이름이 찍힌 후원 영수증 (변형복습 · 디버깅형)

## 배경

토스가 만드는 라이브 스트리밍 클론. 
라이브 방송 중 시청자가 **후원**을 보내면 서버가 즉시 **후원 영수증**(후원자 닉네임 · 후원 금액 · 금액대별 등급 문구)을 응답으로 돌려준다. 
이미 배포되어 잘 돌던 기능이다.

지난 주말, 대형 방송에 동시 후원이 몰리자 신고가 쏟아졌다.

- 어떤 시청자는 자기 영수증에 **다른 사람의 닉네임과 금액**이 찍혀 나왔다고 한다. (개인정보 노출 + 정산 항의)
- 정산팀은 **후원 로그 합계와 영수증에 찍힌 금액 합계가 어긋난다**고 한다.
- 그런데 **한산한 시간대나 QA의 단건 테스트로는 절대 재현되지 않는다.** 방송에 사람이 몰릴 때만 터진다.

앱은 정상 기동하고, 후원 API(`POST /lab13/gifts`)도 단건으로는 흠 없이 동작한다. 
**동시에 여러 후원이 들어올 때만** 영수증이 뒤섞인다.

## 요구사항

1. 이 교차 오염을 **자기 손으로 재현하는 동시성 테스트**를 먼저 붙잡아라. 한산할 때 안 터지는 버그는, 재현 테스트가 없으면 고쳤는지도 증명할 수 없다.
   - `GiftReceiptConcurrencyTest`에 동시 요청 배선까지는 준비되어 있다. **오염을 잡아내는 단언(TODO)** 은 직접 작성한다.
2. 그런 다음 **근본 원인을 제거**하라. 증상만 덮지 말고, 왜 동시성에서만 터지는지 설명할 수 있는 형태로 고쳐라.
3. 등급 문구 규칙과 단건 동작, 후원 로그 적재는 그대로 유지한다.

## 완료 조건 (채점 테스트가 검증)

- **교차 오염 0건** — 서로 다른 입력(닉네임·금액)의 후원 요청을 수십 개 스레드에서 동시에 실행해도, 각 응답 영수증의 닉네임·금액·등급이 **그 요청이 보낸 입력과 정확히 일치**한다.
- **재현 테스트가 저장소에 남아 있다** — 오염을 잡아내는 동시성 테스트가 존재하고, **수정 전에는 실패(오염 검출)**, **수정 후에는 안정적으로 통과**한다. 반복 실행해도 흔들리지 않는다(flaky 금지).
- **단건 동작·등급 규칙 유지** — 기존 단건 후원 응답과 등급 문구(브론즈 / 골드 ≥ 10,000 / 다이아 ≥ 100,000)는 변하지 않는다.
- **정산 정합성** — 처리한 후원들의 DB 적재 합계와 응답 금액 합계가 일치한다.

## 제약

- 추가 의존성 없이 해결한다 (현재 webmvc / jdbc / validation / lombok / h2로 충분).
- 수정 전 테스트가 실패하는 증거(테스트 로그, 커밋 순서 등)를 남겨라.

## 예상 소요 시간

40~70분 — 재현 테스트 작성이 핵심이고, 수정 자체는 몇 줄이다.
