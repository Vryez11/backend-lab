# lab25 — 신고 영상 일괄 비공개가 반쯤만 적용된 채 실패한다

- 분야: 스프링 DB / 유형: 디버깅 / 난이도: 응용
- 패키지: `com.vryez.backendlab.lab25`
- 예상 소요: 1~2시간

## 배경 시나리오

동영상 게시판 운영팀에는 신고가 누적된 영상을 관리자가 한 번에 비공개로 돌리는 **일괄 조치** 기능이 있다. 
관리자가 영상 ID 목록을 넘기면, 서버는 각 영상을 비공개(`PRIVATE`)로 바꾸고 감사용 `moderation_log`에 조치 기록을 남긴다.

**운영 규칙상 이 일괄 조치는 전부 성공하거나 전부 취소되어야 한다** — 목록 중 하나라도 처리할 수 없는 영상이 섞여 있으면, 앞서 처리하던 영상까지 원상 복구되어 아무 것도 바뀌지 않은 상태로 돌아가야 한다.

최근 한 관리자가 신고 영상 5건을 한 번에 비공개 처리하려다 오류 화면을 봤다. 그런데 목록을 다시 확인해 보니:

> "오류가 났으니 아무 것도 안 바뀌었어야 하는 거 아닌가요? 그런데 **목록 앞쪽 영상 몇 개는 이미 비공개로 바뀌어 있고, `moderation_log`에도 그 영상들 조치 기록이 남아 있어요.** 뒤쪽 영상들만 그대로고요."

- 처리 가능한 영상들만 골라 다시 요청하면 잘 동작한다. 특정 상황에서만 터지는 것처럼 보인다.
- 단건 요청 기준으로는 아무 문제가 없다. 동시성·부하·타이밍과 무관하다.

이 장애를 재현하고, 원인을 찾아 **전부 아니면 전무(all-or-nothing)**로 동작하도록 고쳐라.

## 스캐폴드

| 파일 | 역할 |
|---|---|
| `VideoAdminService` | 일괄 조치 로직 진입점 `hideReportedVideos(List<Long> videoIds)` |
| `VideoAdminController` | `POST /lab25/videos/hide` — `{"videoIds": [1,2,3]}` 형태 요청 |
| `ModerationException` | 처리 불가 영상에서 던지는 예외 |
| `src/test/resources/lab25/schema.sql` | `videos` + `moderation_log` 테이블 DDL |
| `src/test/resources/lab25/data.sql` | 시드 5행 |

시드 데이터: 영상 1·2·4·5는 `PUBLIC`, **3번은 `DELETED`**(이미 삭제되어 비공개 전환이 불가능한 영상).

## 완료 조건

- `[1, 2, 3, 4, 5]`로 일괄 조치를 호출하면 처리 불가 예외가 호출자에게 전달된다.
- 예외가 난 뒤 DB를 확인하면 **1·2·4·5번 영상이 여전히 `PUBLIC`이고, `moderation_log`에는 단 한 건의 기록도 없다**(완전 롤백).
- 처리 가능한 영상만 담긴 `[1, 2, 4]`로 호출하면 정상 커밋되어 세 영상 모두 `PRIVATE`가 되고, `moderation_log`에 세 건의 기록이 남는다.
- 앱이 정상 기동하며, 위 시나리오를 검증하는 인수 테스트가 모두 통과한다.

## 제약

- 예외를 `try-catch`로 삼켜 실패를 감추거나, 손으로 `status`를 되돌리는 보상 쿼리로 원자성을 흉내 내지 말 것. 프레임워크의 트랜잭션이 **실제로** 동작하도록 고친다.
- 자체 검증 테스트를 작성한다면 테스트 클래스/메서드에 `@Transactional`을 붙이지 말 것 — 테스트 트랜잭션이 끝에 모든 쓰기를 롤백해 버려, 실제로 커밋되어 남는지를 검증할 수 없게 된다.
- 스키마·시드는 `@Sql({"/lab25/schema.sql", "/lab25/data.sql"})`로 매 테스트 초기화하면 된다.
