# lab21 — 클라이언트 검증만 믿던 업로드 API가 뚫렸다 (구현형 · 스프링 MVC · 기초)

## 배경 시나리오

스트리밍 클론의 영상 업로드는 지금까지 프런트엔드의 폼 검증에만 의존해 왔다.
그런데 QA가 API를 직접 호출(Postman·앱 우회)해보니, 서버가 **아무 값이나 그대로 DB에 저장**하고 있었다.
실제로 운영 DB에서 이런 행들이 발견됐다.

- `handle`(공개 URL에 쓰이는 식별자)에 `My Video`, `-hot-`, `AB` 같은 값이 들어가 공개 링크(`/v/{handle}`)가 깨진다.
- `title`이 공백(`"   "`)이거나 비어 있는 영상이 목록에 뜬다.
- `durationSec`(영상 길이)에 `0`, `-10`, `999999` 같은 값이 저장돼 재생·집계 로직이 오작동한다.
- `category`가 정해진 목록에 없는 임의 문자열이다.

## 요구사항

`POST /lab21/videos` (JSON `@RequestBody`)에 **서버 측 선언적 검증(Bean Validation)** 을 세워,
잘못된 요청은 DB에 닿기 전에 **400**으로 거부하라.
컨트롤러 안에 `if`문을 늘어놓는 방식이 아니라, **DTO 필드에 검증 애노테이션을 선언**하고 `@Valid`로 트리거하는 방식으로 구현한다.

검증 규칙:

| 필드 | 규칙 |
|---|---|
| `title` | 공백·빈 문자열 불가, 최대 100자 |
| `handle` | **소문자·숫자·하이픈만**, 3~30자, 하이픈으로 시작하거나 끝날 수 없음 |
| `category` | `GAME`, `MUSIC`, `VLOG`, `EDU`, `SPORTS` 중 하나 |
| `durationSec` | 필수, 1 이상 43200(=12시간) 이하 |

> `handle`·`category` 규칙은 **정규식(`@Pattern`)** 으로 표현한다.
> (하이픈 시작/끝 금지 같은 경계 조건을 정규식으로 정확히 잠그는 연습이 이 과제의 한 축이다.)

## 완료 조건

인수 테스트가 다음을 확인한다.

1. **정상 업로드** — 규칙을 모두 만족하는 JSON → **201 Created**, 응답 바디에 생성된 `id`가 포함되고, `video` 테이블 행이 **1 증가**한다.
2. **거부 시 DB 무변화** — 규칙을 어긴 요청은 **400**으로 거부되고, `video` 테이블 행 수가 **변하지 않는다**(검증이 컨트롤러 본문·저장보다 먼저 일어난다).
3. `title`이 공백/빈 문자열이면 400.
4. `handle`이 `My-Video`(대문자), `-abc`(하이픈 시작), `abc-`(하이픈 끝), `ab`(2자) 중 어느 것이어도 400. 반대로 `good-handle-1`은 통과한다.
5. `category`가 목록에 없는 값(`FOOD` 등)이면 400.
6. `durationSec`가 `0`, `-5`, `50000`, `null` 중 어느 것이어도 400.
7. `durationSec` 자리에 숫자가 아닌 JSON 값(`"abc"`)을 보내면 **400**으로 처리되고, 이때도 행이 저장되지 않는다.
8. 검증은 반드시 **애노테이션 + `@Valid`** 선언 방식이어야 한다(컨트롤러 내부의 수동 `if` 검사로 통과시키는 것은 완료로 인정하지 않는다).

## 스캐폴드 안내

- `com.vryez.backendlab.lab21` 패키지에 뼈대가 준비돼 있다.
  - `VideoUploadRequest` — 필드만 있다. **검증 애노테이션은 직접 선언한다.**
  - `VideoController` — `upload()`가 미구현 상태다. **요청을 받아 검증·저장·201 응답까지 직접 구현한다.**
  - `VideoRepository` / `VideoResponse` / `Lab21DataSourceConfig` — 완성 상태로 제공(DB 배관은 과제 범위 밖). 손대지 않아도 된다.
- H2 테이블 `video`는 앱 기동 시 `lab21/schema.sql`로 자동 생성된다.

## 제약

- 추가 의존성 금지 — `spring-boot-starter-validation`이 이미 있다. 임포트는 `jakarta.validation.constraints.*`를 쓴다(`javax` 아님).
- 컨트롤러 내부 수동 `if` 검증 금지(완료 조건 8).
- 예상 소요 시간: 45~75분

## 플러스 알파 (선택)

- 검증 실패 시 `{field, rejectedValue, message}` 목록을 담은 **정돈된 400 응답 스펙**으로 반환해 보라. 단, 다른 랩의 응답에 영향을 주지 않아야 한다.
- 같은 `handle`로 두 번 업로드(UNIQUE 위반)하면 400이 아니라 **409 Conflict**로 구분해 보라.
- `tags` 필드를 추가해 원소마다 `#태그` 형식(최대 5개)을 검증해 보라 — 컬렉션 원소 단위 검증.
